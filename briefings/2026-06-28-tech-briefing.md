## Systems / OS

- **libinput root RCE (CVE-2026-50292) — fix in 1.31.3 / 1.30.4 (Phoronix flagged it this week).** A malicious `uinput`/`uhid` device can plant a `\n` in the PHYS sysattr so the `libinput-device-group` udev helper's output is parsed as two key/value pairs → arbitrary **root** code execution. *Why it matters:* not your runtime (JARVIS is headless; local input is deferred to Phase 6) — but it's a textbook untrusted-device-input → newline-injection → parser-confusion bug, exactly the class your March/April adversarial audits hunt across the hand-rolled GGUF / FAT32 / NVMe / BPE parsers. The parsing path is where privilege bugs hide. [Phoronix](https://www.phoronix.com/news/libinput-1.31.2-Security-Fix)
