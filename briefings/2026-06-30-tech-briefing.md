# JARVIS Daily Tech Briefing — Tuesday, June 30, 2026

**Lead — llama.cpp gets (in-progress) support for IBM's Granite Switch, a hybrid Mamba-2/transformer family with runtime adapter-switching (PR #25107, opened Jun 28).** *Granite Switch* (preview: 3B / 8B / 30B) wraps the Granite 4.1 base — a hybrid that interleaves a **majority of Mamba-2 SSM layers with only occasional attention (~9:1)** — with embedded, on-demand adapters: one checkpoint exposes RAG / safety / explainability "experts" toggled by **control tokens** in the chat template, instead of shipping a separate model per task. The new llama.cpp PR adds the GGUF conversion path to run it locally. *Why it matters — two hooks into JARVIS:* (1) it's another hybrid **SSM/transformer** family going mainstream in local inference, and you already built a gated **DeltaNet SSM** path for Qwen3.5's hybrid — Granite's Mamba-2 line is the same architectural class and a natural bench candidate at the 3B/8B CPU-edge sizes *if* you ever add a Mamba-2 kernel. (2) The "single checkpoint, multiple specialist capabilities switched by a token" pattern rhymes with JARVIS's own specialist-agents design (device/network/fs/user) — one weight set, capability picked at runtime. Caveat: Granite Switch is a **preview**, the llama.cpp support is an **unmerged conversion PR**, and Mamba-2 ≠ your existing DeltaNet — a "watch + maybe prototype," not a drop-in.
