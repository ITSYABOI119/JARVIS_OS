**Systems / OS**

- **Never briefed, merged for 7.3 (~Aug 18): the kernel's cross-CPU function-call path was blocking with preemption *disabled* while waiting for remote CPUs to finish their IPI handlers — ByteDance's rework cut fleet-measured worst-case latency for high-priority tasks from ~17 ms to ~1.5 ms (~90%).** The fix is a per-task CPU mask so the wait state is local, which lets preemption be re-enabled before the wait. Read it for the shape, not the patch: it is the same failure mode as your own core-sharing finding — a synchronous cross-CPU wait whose cost is invisible until something latency-sensitive sits behind it — and it lands while K/M4 carry-forward #3 (a dedicated PA core, gated behind the `JARVIS_PB_TICK` flip) is still open.
