# JARVIS Daily Tech Briefing — Wednesday, July 8, 2026

**Lead — llama.cpp landed an ARM NEON FP4 dot-product kernel that dequantizes *inside* the dot via a UE4M3 lookup table (b9886, #25331).** It's the ARM NEON sibling of the AVX2 nvfp4 LUT kernel noted Jul 3 (#23961) — same move: no native FP4, so precompute the 4-bit-float→value table and run the dot over the LUT in SIMD, now on NEON. *Why it matters:* this is the exact `qdot` pattern JARVIS already uses for Q4_K/Q6_K (dequant folded into the dot kernel), now proven on *both* ISAs you target — AVX2 on the x86 deploy box and NEON on the Phase-2 Pi 4 fallback. Not a drop-in (JARVIS doesn't run NVFP4, and your deployed path is AVX2 float-FMA), but it's the reference for making a sub-8-bit *float* format fast on a vector ISA with no hardware support — the template if you ever push your NEON kernels below Q4. [b9886](https://github.com/ggml-org/llama.cpp/releases/tag/b9886) · [PR #25331](https://github.com/ggml-org/llama.cpp/pull/25331)

## Systems / OS

- **Linux 7.3 further restrains the AF_ALG crypto interface behind a new sysctl knob (it was deprecated in 7.2 as a "massive attack surface").** AF_ALG lets user space drive the kernel crypto API directly; after a run of security issues it was deprecated in 7.2, and 7.3 adds a sysctl to gate it further. *Why it matters:* a live case study in the attack-surface argument behind JARVIS's whole bet — mainline is *retrofitting* minimization (deprecate → gate → remove a risky syscall surface), where a microkernel gets it by construction (the interface isn't in the TCB at all). Not your code, but the exact threat-model reasoning your March/April audits and the SHIELD/SEC-039 work run on. [Phoronix](https://www.phoronix.com/news/AF-ALG-Restrict-Sysctl-Linux)
