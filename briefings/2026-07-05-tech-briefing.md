**Lead — OCP "Microscaling" (MX) low-bit formats get a cross-vendor graphics-API standard: MXFP4 / MXFP6 / MXFP8 / MXINT8 (Vulkan 1.4.356, `VK_EXT_shader_ocp_microscaling_types`, Jul 3).** NVIDIA, Samsung, Arm, and Imagination co-authored the extension; it defines the OCP MX float/int types — the shared-per-block-scale, block-quantized 4/6/8-bit family — though not yet tensor ops over them. *Why it matters:* this is the industry converging on a **hardware-blessed 4-bit block-float**, the standardized cousin of your `Q4_K` and the OCP sibling of the NVIDIA **nvfp4** FP4 LUT kernel noted Jul 3. It's Vulkan/GPU-delivered and types-only, so there's nothing to use on JARVIS's CPU-only path today — but MXFP4 is the 4-bit format to track: if it becomes the default hardware quant, llama.cpp's CPU kernels and GGUF tooling follow it, and it's the reference point for where "sub-Q4 on the CPU" is heading. [Phoronix](https://www.phoronix.com/news/Vulkan-1.4.356-Released) · [Vulkan 1.4.356 commit](https://github.com/KhronosGroup/Vulkan-Docs/commit/73836865422f9e28e17069a96cceef6d0ece1ff8)

## Systems / OS

- **Fedora 45 proposes x86_64 CET Shadow Stack on by default (Jul 2).** The dynamic linker would enable hardware shadow stacks for any process whose binary + libs all carry SHSTK markup (already implied by the `-fcf-protection` build default since 2018), hardening the return-address / ROP class at near-zero runtime cost; IBT is a later step. *Why it matters:* this is the hardware-CFI answer to exactly the exploit primitive your March/April parser audits chase (a memory bug → ROP). It's a distro/glibc mechanism, not seL4 — and note your **deploy box can't run it**: the 2700X (Zen+) predates CET, which needs Zen 3+; your **Main PC's 5600 (Zen 3) does** support shadow stacks, so that's the box to experiment on if you ever weigh CET for a bare-metal build. Concept, not drop-in. [Phoronix](https://www.phoronix.com/news/Fedora-45-Consider-Shadow-Stack) · [Fedora wiki](https://fedoraproject.org/wiki/Changes/ShadowStack)

- **Rust Coreutils `cp` broke Ubuntu image builds — Ubuntu reverted `cp` to GNU (Jul 3).** A `-L` (dereference-symlink) argument-handling difference in uutils `cp` made `cp -afL` fail during live-ISO construction; marked "critical" and reverted via the `coreutils-from` package while an upstream fix waits to merge. *Why it matters:* your `install_jarvis_x86.sh` leans on guarded `cp` for ESP/USB provisioning on Ubuntu 26.04, where uutils is the default `cp` — a GNU-vs-Rust `cp` semantics gap is a real footgun for install scripts. Concrete downstream of the Rust-in-base-system push (Trifecta/Canonical, briefed Jul 3). [Phoronix](https://www.phoronix.com/news/Rust-Coreutils-cp-Ubuntu-Images) · [Launchpad #2158691](https://bugs.launchpad.net/ubuntu/+source/coreutils-from/+bug/2158691)
