# JARVIS Daily Tech Briefing — Saturday, July 4, 2026

**Lead — Linux kernel maintainers are moving to *drop* the AI-attribution tag they mandated three months ago (LKML thread, Jul 2–3).** Christian Brauner opened a thread to simplify — or scrap — the `Assisted-by:` trailer the kernel adopted in April, and Jeff Layton posted a patch to remove the AI-disclosure requirement outright. Brauner's objection: "our git history has effectively started to function a bit like a free advertising platform for a bunch of AI companies and their proprietary agents and models," plus inconsistent compliance and message clutter. *Why it matters:* JARVIS is built with heavy AI assistance and your tree's history — including these auto-committed briefings — is exactly the "AI-authored git commits" case the kernel is now arguing over. The kernel is the norm most OSS projects copy, so if the largest project in the world walks back machine attribution, that's the emerging convention for whether/how to annotate AI-assisted commits in your own repo. Note this rolls back only the *disclosure* half of April's "humans-on-the-hook, tag-required" policy — the accountability half stays. [Phoronix](https://www.phoronix.com/news/Linux-AI-Attribution-Again)

## Systems / OS

- **glibc adds `/etc/tunables.conf` for system-wide tunables (Red Hat, ~Jul 3).** glibc tunables (malloc arena count, transparent-hugepage thresholds, hwcap masks, etc.) could previously only be set per-process via `GLIBC_TUNABLES=`; the new file lets an admin pin them host-wide. *Why it matters (dev box, not runtime):* your on-box appliance is musl-on-seL4, so this doesn't touch it — but your Ubuntu build/bench host is glibc, and malloc-arena / THP tunables are exactly the knobs that move large-buffer, memory-bandwidth-bound work like GGUF loads and the native-engine benchmarks. A cleaner place to pin them than exporting env vars per shell. [Phoronix](https://www.phoronix.com/news/Glibc-System-Tunables)
