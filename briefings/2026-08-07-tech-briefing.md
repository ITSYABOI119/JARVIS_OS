**Systems / OS**
- **"Zapscape" disclosed Aug 6: a KVM x86 guest-to-host escape (use-after-free in the shadow-MMU emulation) present in Linux since mid-2020, fixed upstream Jul 21 — public PoC out.** Guest-side actions alone can panic or root the host; it doubles as a local privilege escalation where `/dev/kvm` is world-writable (RHEL ships 0666; Ubuntu defaults to group-restricted). Direct relevance: every JARVIS KVM gate runs on the box's Ubuntu host — the guests are your own seL4 images so the escape path isn't your threat model, but the host kernel should be past the Jul-21 fix before the next long gate run. [Phoronix](https://www.phoronix.com/news/Linux-Zapscape-Vulnerability) · [Zapscape repo](https://github.com/V4bel/Zapscape)
- **Also Aug 6: the "Safe RET Interrupt Vulnerability" — a flaw in Linux's SRSO mitigation on AMD Zen 1–4, demonstrated on Zen 1/Zen 2, patched in kernel Git (AMD bulletin SB-7061).** An attacker timing an interrupt can disrupt Safe RET and weaken the speculative-return protection → possible info disclosure. Both your machines sit in the affected range (2700X = Zen+, 5600 = Zen 3) — but only the *Linux* side: AMD assesses it as a Linux-implementation issue, and bare-metal seL4 runs no Safe RET mitigation at all, so JARVIS-the-OS is untouched while dual-boot Ubuntu wants the patch. Found by Daniël Trujillo (MIT CSAIL). [Phoronix](https://www.phoronix.com/news/Linux-Safe-RET-Interrupt-Vuln) · [AMD SB-7061](https://www.amd.com/en/resources/product-security/bulletin/amd-sb-7061.html)
