**Lead — The Redox OS July monthly finally posted (Aug 11), closing the ~6-week watch this briefing has carried since June 30 — and it lands with a real microkernel number: a Redox Summer of Code developer cut synthetic CPU context-switch cost from ~1.15 µs to ~250 ns, a 4.6× reduction, as part of ongoing EEVDF scheduler work.** That is the metric that decides whether a microkernel design is viable at all — every driver call, every IPC round trip pays it — and a Rust microkernel reaching the low hundreds of nanoseconds is the same order as a tuned fastpath, which is precisely why JARVIS's x86 build runs `KernelFastpath=ON` and accepts sitting outside seL4's verified X64 configuration for it. Keep the comparison honest: this is a *synthetic context-switch* figure, not an IPC round trip, so it is not comparable to JARVIS's own 54 µs Phase-1 IPC measurement or to anything in the current shared-memory PA↔PB path. **Quantization**
- **Never briefed, submitted Aug 7: CubicQuant — "Parametric Non-Uniform Codebooks for High-Throughput LLM Inference with 1-8-Bit Weights" (arXiv 2608.06763).** A *weight*-format paper, notable because the last nine days of this beat have been entirely KV compression (OptR, NOVA-KV, AnchorKV). It maps uniformly spaced integer codes to non-uniform reconstruction levels through a monotonic cubic curve (two shape parameters + one scale), keeping a dense integer code stream — so it decodes regularly, unlike learned codebooks — and **contains symmetric uniform-integer quantization as an exact special case**, i.e. it is a strict superset of the scheme Q4-style formats use. Measured at W4/G=128 against optimally-clipped 4-bit uniform integer: RMSE down 3.90% (Uniform), 13.49% (Gaussian), **28.14% (Laplace)**. Read, not a lever, and be precise about why: kernel numbers are preliminary H200 only, the author states downstream model quality and cross-device end-to-end performance are open, and JARVIS's dequant path is a fused AVX2 `qdot` over the GGUF K-quants — a new format means a new kernel and a new H2-whitelist entry, not a config change. [arXiv 2608.06763](https://arxiv.org/abs/2608.06763)
