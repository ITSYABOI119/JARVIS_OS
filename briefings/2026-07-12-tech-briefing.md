# JARVIS Daily Tech Briefing — Sunday, July 12, 2026

**Lead — Six U-Boot flaws in FIT *signature-verification* parsing: two allow code execution at boot, all six are reached while U-Boot is still reading an untrusted image, *before* the signature is checked (Binarly BRLY-2026-037…042, disclosed Jul 10–11).** The vulnerable code has been in U-Boot since **v2013.07** — 50+ stable releases — and patches are upstream, but each vendor firmware must pick them up. *Why it matters, honestly scoped:* your Phase-2 Pi 4 boots **U-Boot 2026.01** (`boot.scr` → raw `kernel8.img`), which is the *legacy image* path, not FIT + verified boot — so on the current boot flow these specific FIT parsers shouldn't be on your path, and the x86 box boots GRUB/UEFI, not U-Boot. The transferable part is the **bug class**: parse-before-verify on attacker-supplied structured input — exactly the class your own GGUF/FAT32 hardening chases (`buf_read_gguf_string_fixed` overflow-safe subtraction, the `fat32_read_file` sub-sector overflow, SEC-028/029). If you ever add verified boot on ARM, FIT is the thing you'd be enabling, and this is its track record.
