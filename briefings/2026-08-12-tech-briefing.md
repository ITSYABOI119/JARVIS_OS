# JARVIS Daily Tech Briefing — Wednesday August 12, 2026

**Thin day — no seL4 release or CVE, no x86 CPU kernel, no on-path model drop in the Aug 11–12 window. The one substantive net-new item is a paper: AnchorKV — "Anchor-Residual KV Cache Compression" (arXiv 2608.02901), a 20× KV cache shrink that discards ZERO tokens and claims 99% of the full-cache score at 70B scale.** Each KV head keeps a small set of anchor tokens stored exactly and represents every other token as a scaled copy of its nearest anchor — a few bytes instead of a full vector — then refines only the approximations that most move the output. It is structurally the opposite of the eviction-based schemes (no token is dropped, so long-context retrieval has nothing to lose), and it is not a bit-width play like the OptR/NOVA-KV INT2 line already briefed. Still a **read, not a lever**: JARVIS deploys full-precision KV (TurboQuant/RotorQuant deliberately deferred), and the Aug-11 alignment-collapse paper is the caveat that travels with any KV re-budget. But it is now the third distinct KV-compression approach in nine days, and the ~40 MiB/inference KV budget is the thing that eventually reopens. **⚠️ Name collision worth pinning before anyone cites it: there are TWO different "AnchorKV" papers — 2608.02901 (this one, anchor-residual compression) and 2606.17872 (June, safety-aware compression with a refusal anchor). Different mechanism, different authors' framing, same name.** [arXiv 2608.02901](https://arxiv.org/abs/2608.02901) · [HTML](https://arxiv.org/html/2608.02901) · [the June namesake](https://arxiv.org/abs/2606.17872)
