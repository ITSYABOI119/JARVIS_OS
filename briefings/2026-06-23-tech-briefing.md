# JARVIS Daily Tech Briefing — Tuesday, June 23, 2026

**Lead — Linux 7.2 finally removes `strncpy()` from the kernel (merged ~Jun 20; 362 patches over six years).** The last in-tree `strncpy()` callers are gone — the kernel now standardizes on `strscpy()` (guaranteed NUL-termination + a truncation-signaling return) and `strscpy_pad()` where zero-fill is genuinely required. *Why it matters:* `strncpy`'s counter-intuitive NUL semantics are a well-known source of unterminated-buffer overreads and memory-disclosure bugs — exactly the class your March/April adversarial audits hunt for across JARVIS's hand-written bare-metal C (FAT32/NVMe parsers, BPE tokenizer, shmem IPC, the `[PANEL]`/log string paths). If any of those still touch `strncpy`/`strncat`, this is the cue to move to a bounded, always-terminated copy.
