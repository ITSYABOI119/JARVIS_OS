# JARVIS Daily Tech Briefing — Thursday, June 25, 2026

**Lead — A new open-source OS ships *with seL4 as a kernel option*: QSOE v0.1 (Jun 24).** QSOE ("Quick and Secure Operating Environment") is a QNX Neutrino–inspired, dual-kernel platform for RISC-V: the same user-space runs on either QSOE/N (its from-scratch "Skimmer" microkernel) or **QSOE/L (the seL4 microkernel)**. It borrows QNX's small-kernel/everything-in-user-space model, async message-passing IPC, and the resource-manager service model; Apache 2.0, currently targeting SiFive HiFive Unmatched + QEMU. *Why it matters:* a rare, directly comparable reference point — an independent project building a real OS on seL4 with the same architectural bets JARVIS makes (microkernel + user-space services + message-passing IPC). Their seL4 bring-up and resource-manager IPC design are worth a read even though it's RISC-V, not x86-64. [Phoronix](https://www.phoronix.com/news/QSOE-0.1-Released) · [QSOE.net](https://qsoe.net/) · [GitLab](https://gitlab.com/qsoe)

## Systems / OS

- **One-line GCC change to generic x86 tuning → +12% on SPEC (Jun 24).** Intel's Lili Cui raised the branch-mispredict cost in GCC's *generic* x86 `-mtune` table by 3× (modern deep pipelines make mispredicts pricier), worth +12.7% on Granite Rapids and +12.1% on Zen 5 for SPEC 544.nab_r — for generic builds, not `-march=native`. *Why it matters:* it lands in **GCC 17** (next year), so not on JARVIS's gcc 13.3 yet, and your inference inner loop is memory-bandwidth-bound so don't expect tok/s from it — but it's a reminder that `-mtune` is a zero-cost knob for all the *scalar* bare-metal C (FAT32/NVMe parsers, tokenizer, IPC, workload loop). Choosing `znver1`/`znver2` for the 2700X/5600 over plain generic is the same lever, available today. [Phoronix](https://www.phoronix.com/news/GCC-x86-Generic-Mispredict) · [GCC commit](https://gcc.gnu.org/git/?p=gcc.git;a=commit;h=52cd02606b906160bf47001a00b446c35d46f15f)
- **Linux 7.2 hardens the perf tool against malicious `perf.data` (Jun 24, AI-assisted).** The kernel added guards against crafted/corrupted `perf.data` that could subvert the perf userspace tool — landed with help from Claude Opus 4.6. *Why it matters:* it's the same untrusted-input-parsing discipline your March/April adversarial audits enforce on JARVIS's hand-written parsers (GGUF, FAT32, NVMe, BPE) — a reminder that the format-parsing path is where the bugs hide, and that AI-assisted hardening of exactly that path is now landing in mainline. [Phoronix](https://www.phoronix.com/news/Linux-7.2-Perf-Tools)
